# Contributing

Thanks for helping make this the best open Data/ML reference. Every contribution — a typo, a sharper derivation, a new topic — matters.

## Ground rules
1. **`content/*.md` is the source of truth.** Never edit `docs/handbook/` (generated) or the PDF.
2. **Every claim should be checkable.** Prefer a formula + worked number + runnable snippet over prose.
3. **Code must run.** Any code shown via `@@code code/xyz.py@@` is executed by CI. Reference-only code (Spark, Kafka, Airflow, k8s…) goes in a fenced block labelled `# reference, not executed`.

## Workflow
```bash
pip install -r requirements.txt && npm ci --prefix build/mathjax
make test        # all snippets must pass
make outputs     # refresh captured outputs if you changed a snippet
make docs pdf    # check rendering
```

## Writing conventions
- One `# H1` per section file, followed by `tagline: …`. Use `##` for subsections, `###` for cards.
- Math: `$inline$` and `$$display$$` (TeX; rendered by MathJax). Escape literal dollars as `\$`.
- Figures: put the drawing code in `figures/src/`, output to `figures/`, reference as `![alt](figures/name.svg)`. Use the palette in `figures/src/figstyle.py`. Dense plots → PNG (add to `RASTER`).
- Snippets: `code/sNN_topic.py`; put setup noise between `# HIDE` / `# ENDHIDE`. Shared data lives in `code/data/` (git-ignored, generated by `proj01_make_csv.py` and `s02_load.py`).
- Callouts: **Pitfall**, **Pro tip**, **Interview** in bold at the start of a paragraph.

## Pull requests
- One topic per PR; fill in the PR template; link the issue.
- Commits: short imperative subject (`Add focal loss card to 11_deep_learning`).
- By contributing you agree your code is MIT and your content CC BY 4.0.

Good first issues are labelled [`good first issue`](https://github.com/T31SHA/data-ml-handbook/labels/good%20first%20issue).
